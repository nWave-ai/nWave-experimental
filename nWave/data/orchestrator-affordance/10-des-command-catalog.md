## des producing-tools + gates — reach for these instead of hand-editing

Every hand-edit of a checked artifact is a producing tool you didn't invoke.

### 1. Get the list from the tool — this file deliberately carries no copy of it

- **`des --help`** — every subcommand with its one-line purpose (80 today). **`des <verb> --help`** — that verb's flags. Two verbs nest further: `des feature-end {sign,run,run-batch}` and `des loop {probe,inspect,list,arm,tick,recover,stop}` — both require a sub-verb (bare parent exits 2), so the surface is 78 + 3 + 7 = **88 invocable paths**, not 80. Braces in a usage line are NOT always a subcommand set: argparse renders a real subparser as `{a,b} ...` with a trailing ellipsis, and a flag's `choices=` without one.
- **`des verify-catalog-coherence --repo-root .`** — <1s registry↔catalog↔per-gate-file drift check. Run `verify-catalog-coherence` when a gate name looks wrong, before assuming a command is missing.
- A verb absent from `des --help` does not exist in THIS checkout — do not infer it from prose, a plan, or another tree. **And the converse: being LISTED is not being invocable.** `des loop` and `des feature-end` are both listed, yet each errors when run bare. A name is a designation; a runnable path is a property. Counting the first as the second is how a catalog sends someone to a command that cannot run — so whenever a count matters here, it names which of the two it counted.

### 2. Situation → command

| When you… | Reach for | Note |
|---|---|---|
| don't know the next legal step | `des next --feature-id <id> [--format json]` | read-only ledger projection; advisory only, it blocks nothing. Terminal `SliceCommitVerified` beats a stale markdown `Status`. Known stick: a mechanical seal clears the RED requirement, but the advisory still wants an **APPROVED** `ATReviewVerdict` before it moves past "not yet GREEN" — and a NEEDS_REVISION record does NOT satisfy that. If the AT review genuinely happened, record it (`des record-at-review-verdict`); otherwise trust the ledger over the advisory. Never fabricate a verdict to move the advisory. |
| must pick a delivery lane | `des blast-radius --repo . --paths <files...>` | S requires ALL of: ≤2 files, ≤10 changed lines, no boundary file, every consumer count ≤3. **L is tested FIRST and short-circuits** — a boundary file, an INDETERMINATE consumer count, or any consumer ≥10. Only then S/M: anything else that fails an S condition — including an **indeterminate LINE count** — lands on **M**, not L. The two indeterminacies do NOT share a tier (unknown consumers = unbounded fan-in = L; unknown lines = merely not-provably-small = M), and neither is ever softened to S. The line count alone is not the radius — MEASURE. |
| …got tier **S** | charter(PO) → orchestrator applies fix+test DIRECTLY → RED seal → Vera-haiku on the real CLI → `des commit-slice` | pass `--tier S` to CAP it: if the measured radius exceeds the declared tier the commit is REFUSED before anything lands (`BlastRadiusTierExceeded`). Omit `--tier` and NO cap is applied — the S lane is only capped if you say so. RCA optional when the cause is known. |
| …got tier **M** | @prefactoring if needed → ONE DISTILL pass (all ATs) → resident crafter (skeleton-first) → ONE Vera → the FULL feature-end cycle | deep review · env-e2e · full-suite · sign+emit. Never skipped. |
| …got tier **L** | the per-slice cycle, unchanged | emergent design / boundary / many consumers. |
| need a crafter prompt | `des dispatch --mode atdd_pure --project-id <id> --slice <s> --phase A_GREEN --intent "<task>"` | pass the output VERBATIM; never hand-assemble the marker block. Add `--at-kind pytest-regression --regression-test-file <f>` for a pytest AT; `--lane bugfix --defect <d> --regression-test <t>` for a bugfix. |
| dispatch INTO another worktree | the same, plus `--repo-root <worktree>` | stamps `DES-PROJECT-ROOT`. Without it every hook-side gate resolves the feature-delta against YOUR cwd and refuses a feature that exists, complete, in the target tree. |
| dispatch a slice N>1 into an isolated parallel worktree | add `--swarm-isolated --swarm-justification "<why>"` | defers the carpaccio order check to integration. Stamped only from an explicit declaration — never inferred. |
| suspect the feature-delta is incomplete | `des feature-delta-doctor <path>` | one-pass gap aggregator (missing sections, malformed Wave headings, malformed/unjustified Reuse Analysis). Run BEFORE DISTILL and fix every gap together, instead of one gate rejection at a time. |
| need a canonical section heading | `des feature-delta-schema inject --wave <wave>` | emits the exact heading the gates grep for. The analysis inside it is authoring work. |
| are about to check readiness | `des verify-readiness-pre-dispatch --feature-id <id> --slice-id <s>` | the readiness gate's own self-explaining view — run it before hitting the wall. |
| seal an AT before dispatching the crafter | `des verify-red-green --record-red --test-file <f>` then `des verify-negative-at --test-file <f> --all-critical` | two gates: `verify-red-green` records the RedObserved seal, `verify-negative-at` asserts ≥1 negative AT. The seal binds to the file's CURRENT content — re-run it if the file changes. |
| must clear the carpaccio gate for a pytest AT | `des record-at-review-verdict --feature-id <id> --slice-id <s> --verdict APPROVED --reviewer-agent-id <a> --at-kind pytest-regression --regression-test-file <f>` | the reviewer-verdict path. BOTH outcomes seal a record, so a NEEDS_REVISION leaves a readable trace. Gotcha: supplying `--robustness-declaration` + `--robustness-at-scope` with APPROVED runs the robustness-density gate, which can BLOCK the approval and record NEEDS_REVISION instead — check what was actually written, not what you asked for. |
| see a hook-TRUNCATED gate refusal | run the gate directly, e.g. `des carpaccio-slice-gate --feature-id <id> --entering-slice <s>` | the direct run prints the full what/why/how the hook clipped. |
| need a surface Vera can actually drive | `des charter-scaffold --feature-id <id> --area <a>` · `des examine-fixture --out <dir>` | never hand-build an examine harness with precomputed verdict lines. |
| have Vera's verdict | `des record-examine-verdict --repo . --feature-id <id> --slice <s> --charter <path> --verdict PASS --observations "<findings>" --examiner nw-user-examiner` | the record is sealed to the charter's CURRENT bytes. Edit the charter after Vera ran and the PASS is VOID (`ExamineVerdictStale`, exit 2) — re-examine, do not re-record. A recorded FAIL is `ExamineVerdictRefused` (exit 1); INDETERMINATE is `ExamineVerdictIndeterminate` (exit 2), which says the slice carried no observable value at all. |
| commit a slice | `des commit-slice --feature-id <id> --slice-id <s> --message <msg> --path <p...>` | correct-by-construction: stages, stamps `Slice-Id`, folds in verify-then-record, stamps `Gate-Scope` (never hand-add one). `--feature-id` is REQUIRED. |
| share this working tree with another agent | `des commit --owned-paths <p...> --step-id <id> --message <msg>` | holds an exclusive `flock` and builds the commit from a temp index of HEAD + ONLY the owned paths, so a foreign or hook-auto-staged file CANNOT enter it. Bare `git commit` from two agents misattributes work and corrupts the `Step-Id` chain. |
| edited a SKILL.md on purpose | `scripts/hooks/validate_skill_hashes.py --repin` | system pays; never hand-edit the hash baseline. |
| edited frontmatter or a description | `uv run python scripts/docgen.py` then `uv run python scripts/hooks/check_documentation_freshness.py` | `verify-doc-coherence` is the separate evidence-by-execution leg (`des verify-doc-coherence`): it fails a doc claiming a path, npm script or python module the tree does not have. |
| are adding a workflow flavor | `des flavor-scaffold --flavor-id <id>` | the producing tool `mode-registry-completeness` routes to. |
| dispatched a bugfix lane | `des bugfix-pipeline-tick --feature-id <id> --project-root . --defect-id <slug> --action <a> [--stage <s>] --now <iso8601>` | REGISTER it. Cloud stages fan out; box stages (red-seal/crafter-green/vera-examine/commit-slice) allow exactly ONE in-flight defect — a second is not refused but records `BoxLaneEntryDeferred` naming the occupant. An ad-hoc swarm bypasses exactly this. |
| detected a trunk-health signal | `des consolidation-signal-tick --feature-id <id> --project-root . --signal-type <t> --signal-key <k> --now <iso8601>` | the narrow intake for drift / unmerged-work / stale-branch / failing-gate. General bugs stay in `docs/product/backlog.md` until entered via `bugfix-pipeline-tick`. |
| want to know which worktrees are stale | `des sentinel --repo . --target-branch <b> [--owned <names>]` | read-only triage receipt: OWNED / ABANDONED_CANDIDATE / UNDECIDABLE + host capacity. Never mutates, merges or removes. |
| are unsure about a command, a wave, or methodology | `/nw-buddy` | the first agent to consult for any nWave question. Ask before guessing. |

**⚠️ `des verify-worktree-cleanup` — `--check-only`, ALWAYS.** Its `is_ancestor(head, target)`
check returns true for a worktree with zero commits of its own the moment the target branch
merely advances via UNRELATED work. Confirmed data-loss risk: never run the ACT path against
a real, in-progress or shared worktree.

### 3. A gate refused you → the remedy

| Refusal | Remedy |
|---|---|
| `ExamineVerdictMissing` (exit 2) | The gate arms when `docs/product/expectations/<feature-id>/` holds ≥1 charter. FILL the charter and dispatch `nw-user-examiner` on it, then `des record-examine-verdict`. If the slice has NO observable surface, annotate its OWN Slice-Plan row `@infrastructure`/`@prefactoring` — that yields `ExamineExemptNonObservableSlice` (permanently exempt, not deferred). The exemption reads the row's annotation and fails CLOSED: a missing feature-delta, missing row, or malformed Slice-Plan falls back to this refusal. |
| `FeatureUnreconciled` naming slices the feature never shipped | The discriminator is the feature's OWN declared Slice-Plan: foreign slice-ids surface as `unattributable_shipped_slices` (a warning, not a block). Still blocked → either the feature-delta declares no Slice-Plan (add one; with none, every candidate is attributed to you) or the slice IS yours and needs its record: `des reverify-slice-commit` / `des attest-bundled-slice`. |
| `SliceReverifyRefused` — "`--slice-id` is not in the commit's trailer set" | Reverify requires **this** slice-id in the trailer set. If the commit carries a trailer naming a DIFFERENT slice, or a raw `Step-Id:` line, use `des attest-bundled-slice --repo . --feature-id <id> --slice-id <s> --bundle-commit <sha> --reason "<human GO>"` — it relaxes the check to "any recognised trailer" (A2.b), and also demands the `@slice-NN` `.feature` inside the commit (A2.a) with no `@skip`/`@xfail`/`@wip` scenario (A2.c). `--reason` is a human sign-off, not a formality. **If the commit carries NO trailer at all** — a bare `git commit` — BOTH commands refuse and there is no attestation path: re-land the work through `des commit-slice`, which stamps the trailer. Do not keep retrying attest. |
| `SliceReverifyRefused` on any other ground | Read WHICH precondition: not an ancestor of HEAD · already verified · no `@slice-NN` `.feature` in the commit itself · equal to HEAD (a still-HEAD slice belongs to the commit exit gate, not reverify) · predecessor unverified. Each names its own cause; none is a flag you can override. |
| `CarpaccioSliceOutOfOrder` — "entered out of order" | The predecessor carries no `SliceCommitVerified`; land it first via `des commit-slice --slice-id <predecessor> --feature-id <id> ...`. Hard sequencing, not a bug. A genuinely isolated parallel worktree instead declares `des dispatch --swarm-isolated --swarm-justification "<why>"`. |
| `GateInvocationTimeout` (exit 124) | NOT a rejection — box contention. Nothing to fix in the artifact: retry when load and free RAM allow (observed twice at load ~13, then succeeded on the third identical attempt). Never re-author anything in response to a 124. |
| `ReadinessRefused` on a feature-delta that IS complete — in another tree | `des dispatch` resolved `DES-PROJECT-ROOT` against the main checkout. Re-dispatch with `--repo-root <worktree>`. |
| `ATReviewGateRejected` — Gherkin scan on a plain-pytest AT | Every command in the chain takes `--at-kind pytest-regression --regression-test-file <path>`: `des dispatch`, `des carpaccio-slice-gate`, `des record-at-review-verdict`, `des commit-slice`. Omitting it on ANY of them re-arms the Gherkin scan. |
| readiness `sustainability` invariant | The heading is ALWAYS required. Emit `## Test Reuse & Consolidation Analysis`, then EITHER the exact 5 columns (`Existing Test/DSL-Step`, `File`, `Overlap`, `Decision`, `Justification`) OR a `Test-Reuse-Analysis: methodology-exempt` line — and the marker must sit UNDER that heading, BEFORE any table row. **Its own remediation text mis-states this** as heading-OR-marker; a bare marker with no heading is invisible to the parser, and so is a marker placed after the table. |
| `malformed-reuse-analysis` | The gates grep literally. Emit the exact heading `## Reuse Analysis` and the exact 5 columns (`Existing Component`, `File`, `Overlap`, `Decision`, `Justification`); one Decision per row from **{EXTEND, CREATE_NEW} — only those two here**, every CREATE_NEW row with a non-empty Justification, and no duplicate heading. Do NOT copy the sustainability table's wider set: `REUSE` and `CONSOLIDATE` are valid there and `malformed-reuse-analysis` here. `des feature-delta-schema inject --wave design` emits the heading; `des feature-delta-doctor` lists every remaining gap in one pass. |
| `missing-slice-plan` / `malformed-slice-plan` | Same literal-grep discipline, different table: the exact heading `## Wave: DISCUSS / [REF] Slice Plan` and the exact 5 columns in this fixed order — `Slice`, `Value statement`, `Status`, `Annotation`, `Justification`. A dropped or re-ordered column is malformed, not tolerated. The `Annotation` cell is also what the examine-exemption reads, so an absent Slice Plan costs you that escape too. |
| `CommitRefusedMissingFeatureId` | `des commit-slice` requires `--feature-id`: omitting it silently disarmed E1 completeness, the feature-scoped contract gate, the examine gate and the `SliceCommitVerified` record. It now refuses LOUD before any git mutation, naming each. |
| `des commit`: "the following arguments are required" | It needs `--owned-paths <p...> --step-id <id> --message <msg>`. `--message` alone is not a commit — the owned-path set is what makes the scope correct by construction. |
| `validate_component_manifest`: "symbol not found in <file>" | Its grounding is a plain substring search of the cited file, so a dotted `Class.method` can never match Python source. Cite the bare method name. **Gate defect** (decides on the spelling, not on "does this symbol exist"): it also short-circuits on the first bad reference, and a `sut:` with no `::` is skipped entirely rather than reported. |
| `closed-without-reference` (mikado tree) | A lane NAME is not evidence: put in-progress context in the description cell and a **commit SHA** in the closure column — backticked hex, or hex right after the word `commit`. **Gate defect**: the refusal offers "sha / record / gate output" but the code accepts ONLY an extractable SHA, so a record name or gate output alone will not clear it. |
| `mikado-tree-coherence` exit 2 `VERDICT NOT_VERIFIABLE` | A third state that BLOCKS: a check could not be decided, never collapsed into pass. Read which rule went undecided and supply the missing evidence — do not retry hoping for 0. |

**A refusal is data.** Read WHAT/WHY/HOW before acting; if the HOW names a command, run
THAT, not a hand-repair. A refusal you cannot explain is not a reason to reach for
`--no-verify` — that path needs explicit human sign-off obtained BEFORE the commit, and a
commit with no `SliceCommitVerified` is unattested, therefore not done.

### Tech-debt pile drain

`des refactor --pile <path> --agent-cmd 'scripts/refactor_agent.py {prompt}' [--max-parallel N] [--prompt-template <path>] [--driver {python,loop}]` — those are ALL the flags it has (no `--regression-test-file` here, unlike `commit-slice`/`dispatch`/`carpaccio-slice-gate`)
drains pending items from a pile file (`techdebt.md` → `paidtechdebt.md`), one item per
worktree+venv: dispatches the agent, runs fast+impacted green-to-green, merges into a clean
integration branch, and cleans up the worktree/branch on success OR failure.

- **`scripts/refactor_agent.py` IS the shipped actuator** — pass it, do not invent a command. `--agent-cmd` runs as a real executable (`shutil.which` on the first token), so a placeholder or an Agent-tool dispatch is not a valid value. Tune via `NWAVE_REFACTOR_AGENT_{MODEL,PERMISSION,MAX_TURNS,CLI}`.
- **Row grammar** (the SSOT the standing-loops affordance points here for — same
  payload, this session; if you need it as a file, Glob
  `**/orchestrator-affordance/*standing-loops.md`): `- [ ] <item_id>: paradigm=<object-oriented|functional> defect="<defect>" proposed_solution="<solution>" discovered_by=<channel>`
- **`paradigm=`** — the CLOSED set `{object-oriented, functional}` (SSOT `src/des/domain/refactor/paradigm_select.py`). DERIVE it from the TARGET project's DECLARED development paradigm, never from the file's language (a language is not a paradigm) and never from the defect CLASS (`SSOT`, `duplication`, `bug` are taxonomy — that is what `defect=` is for). An unrecognised value REFUSES the row.
- **`discovered_by=`** — optional, from the CLOSED set `{slice-execution, lane-report, systematic-audit, code-search, operational-incident, adversarial-review, gate-refusal, unattributed}` (SSOT `src/des/domain/refactor/discovery_method.py`). Declare the channel that SURFACED the defect, never the one that later verified it; prefer `unattributed` over a classification you cannot support. A row omitting the field is reported in `PileParseReport.unattributed_item_ids` rather than counted as attributed — it is the denominator of yield-per-verification-method.
- **`--driver {python,loop}` is a KNOWN STUB** — parsed, never consulted; both values run the identical path.
