# Native RED Readiness

**Kind**: PROCEDURE. Trigger: the selected oracle cannot yet run through its
declared public boundary, or RED evidence is needed before craft. `nw-distill`
owns the selected oracle/support/argv tuple; `nw-test-design-mandates` owns native
discovery. This procedure does not expand the ATD's write set or task.

## Prepare and observe

1. Read the selected contract, public driving port, native build/test discovery,
   declared dependencies and literal argv/cwd/runtime. Reuse existing test helpers.
   Identify missing oracle supports separately from future production targets.
2. Author only declared oracle/support bytes for an oracle-authoring task. A
   manifest-only task returns facts without file edits. Do not create production
   modules, assertion-error stubs, scaffold markers or a fictitious public API
   merely to manufacture RED. Return a missing production seam to DESIGN with a
   concrete constructive counterexample.
3. Execute the declared native recipe, or ask the host to execute it unchanged
   when the role ceiling lacks execution. Prove collection/build/setup succeeds
   and the promised public stimulus reaches an assertion of the business outcome.
4. Classify authentic output: promised outcome absent/wrong is semantic RED;
   compile/import/dependency/fixture/startup/capture failure is BROKEN; insufficient
   native attribution is INDETERMINATE. Exit status, counts or an assertion-like
   exception class alone do not establish the cause. Already satisfied behavior
   remains GREEN and requires no artificial production change.
5. Return classification and evidence in the existing role/recording contract.
   Repair an oracle/support defect within authority; route missing substrate or
   contract to its owner. Do not emit another `red-classification.md`, handoff
   ledger or guessed destination. Preserve the original obligations.

## Negative observations

Construct a falsifier for each relevant promise: the wrong business outcome,
state loss, duplicate consume, forbidden transition or early response must be
observable when the contract distinguishes it. Naming a test `rejects` or marking
it `negative_at` does not prove that observation. Use business-readable native
identifiers; do not rename valid native tests just to satisfy a syntax proxy.

## Optional mechanical tools and their ceilings

`verify-test-runner` is a pytest producer, not a universal executor.
`verify-red-green` (optional pytest/JUnit adapter: `src/des/cli/verify_red_green.py`), negative-at, execution-reach and doc-coherence helpers are
optional and usable only under their actual applicability/evidence contracts.
A JUnit-consuming tool needs authentic native JUnit output if selected; it does
not require every project to install a reporter, switch runner or synthesize
JUnit/counts from arbitrary summaries. Choose existing richer native evidence
when needed, or retain the tool's limitation explicitly. Mechanical seals bind
identities; the role judges semantic failure cause.

For a stable native public entry, invoke absent behavior through its real runtime
dispatch and compare captured public outcomes. Do not assume lazy-import or
collection semantics from Python in another stack. Where compilation requires
future production, identify the timing limitation rather than converting a
build error into a business assertion with a stub.

## Handoff

Supply authentic source/oracle/support identity, selection, argv/cwd/environment,
observed failure and its local reason through existing channels. Retain wrong-
reason evidence; do not suppress it or call it intended RED. Native launch/setup,
machine capability (ports, writable cache/temp, space/inodes) and provider/auth/
quota/timeout failures are distinct from product rejection. Unknown is not zero
or PASS. The host owns execution/continuation; DES records facts, not authorship.
