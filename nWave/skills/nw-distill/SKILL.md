# nw-distill

Compile the value observation and executable oracle from durable product and
architecture authority. Provide only consumed facts to the resident owner; do
not create a workflow handoff or execute delivery.

For an uncertain boundary, use the existing constructor and resident oracle
delegation to make one concrete public-port case executable before expanding the
affected design or solution. Preserve the RED observation for that oracle;
DELIVER consumes the resulting oracle to implement the change. If the oracle
consumer cannot express the case, return its specific missing semantic question
and counterexample to the design owner. Do not invent a handoff, choose a
successor, or create a separate cycle for an internal technical fragment.

Read `~/.claude/skills/nw-role-invocation/SKILL.md` before delegating. The
oracle author is the installed `nw-acceptance-designer`, natively or via
`des oracle --repo-root ROOT --value N`; never a generic persona.

Before craft, MUST read `~/.claude/skills/nw-at-completeness-check/SKILL.md`
for before-code alignment. Reuse a prior adequate alignment when the original
value, selected contract, and findings are unchanged; do not repeat its examiner
assessment or ATD review. Only for new, changed, or unresolved semantics, supply
the same selected behavioral contract to ATD and an independent native
`nw-user-examiner` preimplementation assessment, then supply both outputs to the
existing ATD reviewer. Human scope authority remains unchanged. Follow
`nw-role-invocation` for the source-blind evidence boundary and current DES
limitations. Alignment is part of DISTILL, not runtime acceptance.

`des distill --repo-root ROOT --input -` accepts the closed complete acceptance
manifest (schema_version 2).
An incomplete legacy selected revision (`SelectedRevisionIncomplete`) or a
`SelectedRevisionRealignmentNeeded` after changed DESIGN is corrected by a
complete replacement. When new or revised acceptance facts are needed, the caller
first invokes the installed `nw-acceptance-designer` natively, or explicitly uses
`des prepare-role --role acceptance-designer --task selected-revision-recovery --value N --finding -`
then its printed `des invoke-role` command, to return the complete v2 manifest
from current B and changed DESIGN. The caller then passes its reported bytes unchanged to
`des distill --repo-root ROOT --replace-current --input -`. Changed behavior does
not justify replacing unrelated B locator/supports/ordered argv/index with DESIGN
defaults; the owner may revise them deliberately with a reason. The prior revision
is preserved until then and no role authors handoff Markdown.
If the returned document still does not answer why the selection was wrong, do
not replay the same recovery INPUT: submit a corrected `--finding -` through
the same `prepare-role`/`invoke-role` pair. A corrected finding for the same
authority binding seals its own distinct INPUT beside the earlier one, so the
caller invokes the new INPUT rather than rebuilding the handover.
The tuple oracle/supports/obligations/ordered argv/index is complete; never infer
an executor from a filename. DES deterministically writes the acceptance brief
and persists the same typed obligations, oracle and support locators in the
existing handover. It never invokes a provider, chooses a successor, or executes
craft.

On `SelectedRevisionIncomplete`, `SelectedRevisionRealignmentNeeded`, or an
oracle refusal, read `~/.claude/skills/nw-auto/SKILL.md` and use its recovery
table, the sole owner of recovery classes and commands.
