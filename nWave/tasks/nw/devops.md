# NW-DEVOPS

Use this optional step only when deployment, environment, observability or
recovery risk affects the Request. Do not impose DEVOPS on work with no platform
delta. Read current product and architecture authority; resolve a real
contradiction with its owner rather than creating a side ledger.

Invoke the installed `nw-platform-architect` role for operational facts,
including observable constraints, actual environment-native verification
commands, rollback and failure behavior. The role returns semantic facts; it
does not edit an architecture document, KPI file, handover or CI config merely
to satisfy this step.

<!-- DES-WAVE: devops -->

Send one closed `OperationalDocumentInput v1` to
`des devops --repo-root ROOT --feature FEATURE_ID --input -`, or select the
configured project/epic/slice scope. The provider-free constructor publishes
the configured authority and adjacent `.operational-facts.json`. Select that
sidecar explicitly for PO with `des po --operational-facts PATH`; DISTILL then
uses the selected constraints to build executable observations. Do not invoke
the retired `--authority`/`--section` role-writer form.

If an existing authority already answers the question, reuse it without a
role turn or duplicate document. No automatic SSOT bootstrap, KPI YAML
mutation, dashboard, status report or separate handoff is required.
