# Atomic selected acceptance: fixture builder + bounded real-host probe (Value 3)

**A test instrument, never a CI gate and never product.** No runner, hook, schema or gate is added to nWave. DESIGN grammar stays 1; DISTILL target is 2. Evidence for the orchestrator only.

## Two separable jobs
1. **Fixture build (free, deterministic)**: every case's repository is constructed through the REAL `des` CLI in a fresh git repository (`des discuss`, `des design --value/--shared`, `des distill`, `des oracle`). Grammar comes from `des <step> --help` / `des discuss --describe-input`; inputs are finite files under `fixtures/` (orders feature drawn from the accepted design dossiers K/R). No paid PO call is used. Two labelled exceptions, both recorded in `fixture.json`:
   - `HISTORICAL_LEGACY_V1_SEED` (`recovery-incomplete-legacy` only): persisted v1 acceptance trio written into `handover.json`, mirroring `_seed_persisted_v1_selection` in `tests/des/acceptance/distill_document_construction`. The v2 constructor refuses v1 input, so no constructor can author it.
   - **Setup-only fake provider**: `des oracle` buys one acceptance-designer turn. Build steps that need it use the existing `tests/des/acceptance/fake_provider.py` script (as the public acceptance tests do) to write the oracle files, then `des oracle` MEASURES them (OracleNotRed / ORACLE-RED). It is never on the evaluated host's PATH, and no credential or provider env is inherited by setup steps.
   Each step declares its expected exit / `WHAT` / text; a mismatch makes `fixture_status` `setup-failed` and **the case is never handed to a host**. A step may declare `pending_current` (a precisely matched not-yet-implemented refusal) which yields `pending-v2-red`, kept distinct from `setup-failed`; no case currently uses it because v2 persistence now constructs (it was observed once as `SelectedRevisionIncomplete` on a complete v2 distill before that landed).
2. **Host probe (paid; parent only)**: the ordinary installed outer wave receives the unchanged case request plus a declared automatic/delegated collaboration condition. Claude runs `/nw-design` or `/nw-auto` via `claude -p`; Codex runs `$nw-design` or `$nw-auto` via `codex exec`. No inner-role override, injected role instructions or restrictive tool allowlist is used. The wave must reach the expected installed specialist; reading its definition alone does not establish dispatch. `--model` is explicit. A `claude` stub refuses purchased DES turns (`EVAL-NO-PROVIDER`) only for declared `provider_bounded` recovery cases; scope cases use the real provider. Such bounded recovery cases cannot prove completion of the recovery. Codex dispatch remains indeterminate when native evidence does not identify an actual role invocation.

The unredacted native originals are retained at `~/.nwave/recovery/atomic-selected-acceptance-20260921/role-boundary-install/clean-profile/.codex/sessions/2026/09/21/`.

`--self-test` checks the transcript parser on synthetic events shaped after recorded Claude (`tool_use`/`tool_result`) and Codex (`item.started`/`item.completed` `command_execution`, `/bin/bash -lc`) streams: narration/`echo` is not a des command; started+completed count once; heredoc bodies are skipped; read-only `des state`/`--help` never displaces the first operation; a command with no recorded result fails.

Exit codes: 0 all pass/built, 1 a fail, 3 not-run, 4 a setup-failed fixture, 5 pending-v2-red.

## What is observed and how a case passes
Per run (`<output-root>/<host>/<case>/result.json`, plus `fixture.json`, `transcript.jsonl`): each shell tool call is parsed into des invocations (statements, not text); **the tool invocation and its result are recorded separately** (`des_operations[].command` vs `.result`, `.terminal`); read-only inspection is listed apart (`read_only_before_first_mutating`); the first **mutating** des operation is `first_mutating_des`.
Pass requires all of: the first mutating operation matches `expected.first_mutating`; no forbidden pattern matches any mutating operation; where stated, the command carries the required input (`schema_version` 2 / states `X`); the operation has a recorded result with a DES terminal; and for `effect: success-and-handover-changed` the terminal is `Success` **and** the handover bytes changed. Text alone never passes. Case X's no-operation alternative is governed by the residual controls below (narration never passes). Auth/provider absence, missing model, missing CLI or installed role → `not-run`, never fail or pass. A des call hidden in `$(...)` is `fail` (unclassifiable).

Cases: recovery (incomplete legacy, substrate broken, product missing, design-after-B) and scope dossiers K, R, X, U and single-value control. Credentials are passed to the host child by env NAME only and never read, stored or printed.
Deterministic installed-agreement oracle: `tests/installer/acceptance/test_installed_specialist_knowledge.py`.

## Residual controls added after review (Value 3 followup)
- **Stdin JSON**: the recorder captures the real stdin; `expected.input_json` (`{"schema_version": 2}`) is checked by parsing it, never by regex over command text. Missing/non-JSON stdin fails.
- **X alternative**: no des operation never passes on narration. A completion claim fails; an explicit `rejected`/`indeterminate` decision naming absent X and its decision owner passes; anything else is verdict `needs-semantic-review` with the full final text stored (`final_text_for_review`) for the parent to judge independently.
- **Installed-only instructions**: before the host, source `nWave/` is `git rm`ed and committed in the subject repo (`source_guidance_absent`), and the host is not run if it reappears. Preflight requires the installed role plus `nw-design` (scope) or `nw-auto` + `nw-distill` (recovery) for that host, else `not-run`. `result.json` records `role_declared` (installed tools/skills), `read_evidence` (Read/Skill/Glob paths) and `source_guidance_reads`; rereads of preloaded skills are not demanded. The outer wave has ordinary host tools; the installed specialist retains its own declared tools. Permission configuration is stated below. Unsupported host aliases remain `not-run` until a real canary.
- **Terminal-only cases** (`effect: terminal`) are labelled `claim_class: first-command-class`; a usage/argument refusal fails; `provider_bounded` cases require `EVAL-NO-PROVIDER`. `recovery-substrate-broken` additionally requires `tests/` to have changed before the first `des oracle` (support repair evidence via recorder `tests_before`). **Limit**: a new RED is not observable under the bounded no-provider stub, so it is not claimed.
- **Redaction / timeout / auth**: exact values of passed credential env vars are redacted from transcript, stderr and recorder records. A timeout keeps partial redacted output and yields verdict `timeout` (`spend_attempted`), never `not-run`. Auth markers with no des actions are `not-run` even at exit 0.
- **Runtime drift**: `DELIVERY-RUNTIME tree=` is recorded per declaring setup step (`runtime_trees`); differing trees yield `unqualified` (exit 8). Discuss/distill declare none. This says nothing about a final frozen build; the final candidate rerun is still required.
- **F12**: `recovery-design-after-b` expects DISTILL realignment because the human asked for it; DES also offers `des design --replace-current` to restore DESIGN, which this case treats as a fail (documented narrow path).
- New verdicts/exit codes: `needs-semantic-review` 7, `unqualified` 8, `timeout` 9.
- Local controls: `--self-test` covers X narration, JSON stdin, timeout+redaction, missing skill, source-guidance removal, usage refusal, support repair and runtime drift.

## Recorder path independence and invocation boundary (canary correction)
Real Claude canary (`scope-single-value-control`, indeterminate, evidence preserved) showed two separate causes:
1. **Instrument defect (fixed)**: the host shell resolved the installed `.claude/bin/des` ahead of the PATH shim, so no record was written. Recording no longer depends on PATH: the probe also sets `PYTHONPATH` to a generated `sitecustomize` (`des_recorder.INTERCEPT_HOOK`); when the installed `des` python script starts it re-execs the recorder, which runs that same installed script. No installed/source/runtime byte changes; the frozen runtime identity is still the installed tree. `--self-test` adds a login shell whose profile prepends the installed bin. Limits: `python -m des.cli` or a cleared `PYTHONPATH` is unseen (mismatch with transcript stays indeterminate); not yet observed against real Claude's shell snapshot.
2. **Invocation boundary (corrected)**: the installed `nw-solution-architect` returns a closed semantic manifest for its caller to submit through `des design --input -`. The initial role-direct canary measured only that producer and remains indeterminate. Current probes invoke the installed outer wave, which owns delegation and constructor invocation. Actual installed-host results, rather than this invocation change alone, establish whether the connection works.

## Noninteractive permissions, collaboration mode, permission blocks (canary correction 2)
- Subject repos are isolated, so hosts run without approval: Claude `--permission-mode bypassPermissions`; Codex `--dangerously-bypass-approvals-and-sandbox` (no `--sandbox`). No remote/push/install actions are authorized.
- The prompt appends a fixed note stating the experimental condition "automatic/delegated" collaboration for BOTH hosts after the unchanged request (not an answer or command hint); `result.json` records `collaboration_mode`.
- A host permission refusal (`permission_denials`, permission-worded error tool_result, declined Codex item) with no DES records yields `host-permission-block` (exit 6, `spend_attempted`, raw `permission_blocks`): not pass, not product, not recorder bypass. Commands that ran without records stay `indeterminate`.
- Codex role dispatch now needs a real `des ... <role>` command at statement start; reading/`sed`/`ls` of `agents/<role>` is not dispatch. Limits: no native dispatch schema observed, so Codex stays indeterminate in practice; Claude counts only Agent/Task `subagent_type`.

## Native Codex descendant evidence (canary correction 3)
Codex `exec --json` stdout shows only the root thread; a delegated child really executes in its own native session under the installed isolated profile's `.codex/sessions`. A recorder count larger than root stdout was therefore misread as recorder bypass.
- After the host exits, `run_probe` reads only `<installed-home>/.codex/sessions` (no global scan, no pid guessing): root = stdout `thread.started.thread_id` with cwd equal to the subject repo; descendants = rollouts whose FIRST `session_meta` has `parent_thread_id` in the selected set and the same cwd. Later repeated meta lines are ignored. Copy retained as `native-sessions.jsonl`; path/sha256 in `native_sessions`.
- Shell commands are read only from the observed `custom_tool_call exec` → `tools.exec_command({"cmd":...})` shape; other native calls (spawn_agent, wait_agent) are kept as `other_native_calls`, not interpreted. Each operation carries `origin` (root/child), `thread_id`, native call id/line, output. `des_operations` remains root stdout; `native_operations` is all threads in timestamp order.
- Role dispatch proof = a linked descendant's native `agent_role`; role names in command/read text prove nothing. Mandatory skill reads stay in `read_evidence`, distinct.
- Records are matched to observed operations by normalized argv (`attribution`). Observed-without-record stays recorder bypass; record-without-observation is `unattributed` (indeterminate).
- `--replay-native CASE_DIR --installed-home HOME` writes `result.amended.json` beside the untouched raw `result.json`. Replay of the Codex scope-single-value-control canary: root stdout 9 des calls, native root 9 + child 7, 16/16 records attributed, child role `nw-solution-architect` proven; amended verdict `fail` (no mutating des; the child/root refused design for missing substrate) — a refusal is never a pass.
- Limits: replay takes handover-chain endpoints from the recorder log; ordering across threads uses native timestamps; other native call shapes (function_call shells) are unobserved and ignored.

## Native evidence repair (review round 4)
- Live Codex runs now judge with native root+descendant operations (root stdout only when no native session is found).
- A native call carrying several `tools.exec_command` commands has one shared output that cannot be attributed: those results stay `None`. Native `exit_code`/`is_error` are unknown (`None`), never "not an error"; `success-and-handover-changed` requires `is_error is False`. The recorder result stays the per-call authority.
- Live `native-sessions.jsonl` is redacted with the known passed credential values (sha256 is of the untouched Codex original). Offline `--replay-native` cannot know past secrets, so `result.amended.json` keeps hash-only command/output provenance and copies no session lines.
- Cross-thread first-mutation order is `indeterminate` when native intervals tie/overlap and no earlier record changed the handover (the recorder chain proves order); same-thread order is unaffected.

## Recovered-path retry classification (evaluation only, never DES policy)
- Raw first-attempt verdict and metric are unchanged and stay visible; a first attempt that fails is still `fail` in the raw result.
- New verdict `recovered-path-retry` (exit 10, distinct from `pass`) only for `success-and-handover-changed` cases, when EVERY mutating attempt before the first Success is a refusal of the expected semantic step (no forbidden match) with recorder `WHAT: InvalidRepositoryRoot`, `TURNS-BOUGHT=0`, a non-zero known exit and byte-identical handover before/after, and the Success has exit 0, a valid input payload, `DELIVERY-OUTCOME: Success` and a changed handover. A wrong-step, forbidden, provider-turn, side-effecting, unknown-outcome or unknown-exit attempt, a malformed payload, or no Success stays `fail`/`indeterminate`. Cross-thread order uncertainty is still indeterminate first.
- Forbidden patterns apply before and including the recovery; operations after it are retained in the records and are not described as the initial step. Whether an unspecified fixture is a product bug is not inferred by string matching; that stays independent review. Native recorder is the result authority; narrative never passes.
- Existing `provider_bounded`/terminal cases keep first-command-only limits; nothing here claims real role execution or a complete RED from the stub. `--replay-native` (Codex) uses the same evaluator; retained Claude results are not replayed (would need a new framework). `--self-test` adds `retry:` counterexample controls.

Recovered-path-retry guards (end-to-end via `evaluate_records`/`downgrade_unproven`): recovery applies only when the sole raw failure reason is the first attempt's "observed outcome … not Success". A `final_forbidden` claim, a forbidden operation anywhere (including after the Success) or any other raw failure stays plain `fail`. Raw reasons are appended after the recovery sentence. Attribution, hash-chain and unordered-mutation gates run first; missing role dispatch or a source-guidance read downgrades the verdict to `indeterminate`. Post-success continuation is not judged as the initial step, only screened for forbidden operations.

## Public-observation capture (Value 4, examiner input)
Producer run (caller-owned selection; DES never runs it, selects events or judges the trace):
`python tests/evals/atomic-selected-acceptance/public_observation_capture.py --repo-root ROOT --candidate SHA --calls-jsonl RAW --selection-json SELECT --output PACKET`
`SELECT` is `{"scenarios":[{"id","substrate","purpose","seqs":[raw global seq...]}]}`. Only the named records are mapped; equal states are interned, original seq gaps are kept, the repo root becomes `<repo>`. The packet is written only after `read_packet` self-checks it; on failure the exit is nonzero and no packet exists. Local control: `--self-test` (offline).
- Size: the packet is capped at 65536 bytes (the full selected trace is ~84 KB), so select fewer events; seq gaps are allowed and visible to the examiner.
- Limits: this is not a native replay and runs no verify command. Raw stdout/stderr are caller evidence, unredacted beyond the path screen. Each scenario's substrate is caller-declared and unverified; `mock_provider` observations cannot establish installed-host behavior.
